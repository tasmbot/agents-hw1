# Сравнительный отчёт — ДЗ №1, вариант Б

## Цель

Сравнить прямую разработку мини-трекера учебных задач и разработку с OpenSpec при одной и той же постановке.

## Факты эксперимента

Модель: `openai/gpt-5.6-terra`.

| Критерий | Direct | With-spec |
|---|---:|---:|
| Время разработки | 5 мин | 45 мин |
| Обращения к модели | 2 | 13 |
| Автотесты | 5/5 PASS | 6/6 PASS |
| T1–T5 | PASS | PASS |
| Адаптивность после исправлений | PASS | PASS |
| Формальная спецификация | нет | да |
| Строгая валидация OpenSpec | не применялась | PASS |
| Статус OpenSpec | — | 15/15, `all_done`, изменение архивировано |

## Наблюдения

Direct был быстрее и потребовал меньше обращений. В нём после проверки интерфейса исправлялся перенос процента в мобильной карточке статистики.

With-spec потребовал больше времени, но сохранил proposal, spec, design, tasks и архив изменения. В процессе были зафиксированы UI-01 (выравнивание кнопки) и UI-02 (граница адаптивной сетки 390/391 px), после чего уточнены требования и CSS. В доступной истории подтверждены PASS для UI-01, UI-02, адаптивности и T1–T5.

## Ограничения

Это одна попытка для каждого подхода и один небольшой проект. Время и число обращений — наблюдаемые значения, без отдельного учёта времени человека и модели. Стоимость и токены не зафиксированы. Скриншоты не приложены: в доступных материалах их нет; placeholders оставлены в README.

## Вывод

В этом эксперименте оба подхода дали работающий результат. Direct оказался эффективнее по времени для небольшой конкретной задачи. OpenSpec дал более прозрачную историю требований, исправлений и проверок, но потребовал больше взаимодействий и не исключил первоначальные UI-дефекты.
