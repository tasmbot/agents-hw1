# Design

## Context

См. `proposal.md` и `specs/tracker/spec.md`. Трекер является автономной страницей без CDN, внешних библиотек, API-ключей и внешних API. Его данные состоят из задач с полями `id`, `title`, `hours` и `done`; исходный набор задан в постановке.

## Goals / Non-Goals

**Goals:**

- Разделить доменные правила и работу с интерфейсом.
- Обеспечить предсказуемые расчёты метрик, фильтрацию и валидацию.
- Сохранить доступное, читаемое отображение на ширине 390 px.

**Non-Goals:**

- Сохранение в `localStorage`, обработка недоступного хранилища и особенности `file://`.
- Любые возможности, не заданные в `brief.md`.

## Decisions

### Модель данных и начальное состояние

Каждая задача представляется объектом `{ id, title, hours, done }`. Начальное состояние содержит «Чтение» (2, `true`), «Практика» (4, `false`) и «Повторение» (2, `false`); выбранный фильтр хранится отдельно от списка задач.

**Обоснование:** фильтр является состоянием представления и не должен менять данные, от которых вычисляются общие метрики.

**Альтернатива:** удалять не подходящие фильтру задачи из списка. Она отклоняется, потому что нарушает требование независимости метрик от фильтра.

### Разделение модулей

`domain.mjs` содержит чистые функции: проверку полей, добавление, удаление, переключение `done`, расчёт метрик и отбор задач по фильтру. `app.mjs` хранит текущее состояние, связывает события формы, кнопок и фильтров с доменными функциями и повторно отображает интерфейс. `index.html` задаёт разметку, а `styles.css` — оформление и адаптивность.

**Обоснование:** чистые функции можно проверить через `node:test` без браузера; DOM-слой остаётся небольшим.

**Альтернатива:** выполнять расчёты и валидацию в обработчиках DOM. Она отклоняется, поскольку усложняет независимое тестирование правил.

### Расчёты, фильтрация и валидация

Расчёт метрик всегда принимает полный список задач: `totalHours` — сумма `hours`, `doneHours` — сумма часов задач с `done=true`, `progress` — `Math.round(100 * doneHours / totalHours)` при ненулевом `totalHours`, иначе `0`. Функция фильтрации возвращает видимый список для значений «все», «активные» и «готовые», не изменяя исходный список. Валидация применяет `trim` к названию и принимает часы только в диапазоне 0.5–24 включительно, кратные 0.5; пустое значение часов не преобразуется в ноль.

**Обоснование:** единый источник расчётов исключает `NaN` и `Infinity`, а также расхождение метрик между фильтрами.

### Отображение ошибок и пустого состояния

При ошибке валидации `app.mjs` оставляет значения полей без изменений и выводит сообщение возле соответствующего поля; добавление не выполняется. После удаления последней задачи список отображает пустое состояние, а метрики получают результат расчёта для пустого списка: 0 часов и 0%.

**Обоснование:** это прямо сохраняет введённые данные и оставляет интерфейс рабочим при пустом состоянии.

### Адаптивная компоновка

Блок метрик содержит отдельные подписанные элементы «Всего», «Готово» и «Прогресс». Стили на ширине 390 px используют компоновку, при которой все три подписи и значения помещаются в пределах области без обрезания и горизонтальной прокрутки; значение `100%` учитывается как допустимое значение метрики.

**Обоснование:** отдельные элементы позволяют перестроить блок метрик без потери текста на узком экране.

**Альтернатива:** фиксировать одну горизонтальную строку. Она отклоняется, потому что может переполнить ширину 390 px.

### Компоновка формы

На ширинах, достаточных для трёх столбцов, форма использует grid-строку; кнопка выравнивается по верхнему краю полей ввода, а не по нижнему краю контейнера поля с сообщением ошибки. Для этого label имеет предсказуемую высоту, а кнопка получает соответствующий верхний отступ.

При ширине менее `42rem` форма переходит в одну колонку с явным вертикальным интервалом между полями и кнопкой. `42rem` — начальный порог, рассчитанный с учётом фиксированного столбца часов, кнопки, промежутков и полезной ширины поля названия; его достаточность подтверждается только ручной проверкой рядом с порогом.

**Обоснование:** правило `align-self: end` привязывает кнопку к нижней границе контейнера с областью ошибки и опускает её ниже input. Порог `390px` переключал обратно в трёхколоночную сетку уже на 391 px. Новая компоновка устраняет обе причины, не затрагивая обработку данных.

## Risks / Trade-offs

- [Дробные часы могут дать неточное представление чисел с плавающей точкой] → принимать только шаг 0.5 и проверять контрольные расчёты 25% и 75%.
- [Узкая компоновка может обрезать длинные подписи или значение 100%] → вручную проверить область 390 px, все три метрики и отсутствие горизонтальной прокрутки.
- [Проверки DOM не выполняются в `node:test`] → автоматизировать только доменные правила; форму, кнопки, тексты ошибок и ширину 390 px проверить вручную.

## Migration Plan

Миграция и откат не требуются: добавляется автономный мини-трекер без внешних интеграций и существующих данных.
